# Wac 運用クイック手順

## 1. 基本ルール

- まずローカルで動作確認する
- 画面と数字を人間が確認する
- 問題がなければ「確定」とする
- 確定後にコミットと push を実行する
- コミットメッセージは日本語にする

---

## 2. 実行フロー

### 修正前
- 何が起きているかを1行で整理
- 期待値を決める
- 再現手順を確認

### 修正中
```bash
npm run dev
```

### 確認時
- 画面が意図どおりか
- 文字や数字が正しいか
- 重複や誤動作がないか
- PDF/出力が必要なら確認

### 確定時
> 「確定です。GitHub に送ってください。」

---

## 3. 送信手順

```bash
git status --short
git --no-pager diff -- src/App.jsx
git add src/App.jsx
git commit -m "現場名重複防止と一覧重複除去を修正"
git push origin main
```

---

## 4. よく使うコミットメッセージ

- 「現場名重複防止と一覧重複除去を修正」
- 「同名現場の追加防止と一覧表示の重複解消」
- 「現場追加時の重複チェックと画面表示修正」
- 「重複現場の修正と再作成時のガードを追加」

---

## 5. 重複修正時の確認ポイント

- 同名現場を追加しようとしたときに止まるか
- 一覧に同名が2件出ないか
- 既存の重複データを削除した後、正しい1件だけ残るか
- アラートの後に処理が続かないか

---

## 6. 重要な判断基準

### OK
- 実務要件を満たしている
- 画面の動作が正しい
- 数字が合っている

### NG
- エラーが残る
- 意図と違う動作
- 重複やズレが残る

この場合は修正して、再確認してから確定する。

---

## 7. 一番大事なルール

ビルド成功だけでは不十分です。
実際の画面で動作確認して、問題ないと判断してから確定します。

その後に、Claude Code がコミットと push を行います。
